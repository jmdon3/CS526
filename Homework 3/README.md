1: Introduction: This problem required us to create a program that takes a file from standard in, identifies whether or not each line is a palindrome (spaces ignored), and then prints true or false for each line depending on the result and then print the count of lines that are palindromes.
Algorithm: To do this I created 2 different functions within the program. The first identifies whether or not a string is a palindrome. It does this by checking for edge cases, saying that a string of 1 character is a palindrome, and that if it has 2 characters and the characters are the same then it is a palindrome. For strings of greater than 2 characters, it checks that the first and last character matches and then calls the function recursively for the string less the tested characters. If none of the above fits the string, then false is returned. Next is a function that handles running the palindrome function multiple times for a file. This takes the file, goes through it by line with a for loop, removes spaces as they are irrelevant to the palindrome function and do not need to be preserved and then run the palindrome function on it. The result is then stored in a string and a tally of lines that return true is kept. At the end of the loop, that tally is tagged onto the string and then the string is returned. The rest of the program gets the file to be tested from standard in, ensures that it is compatible, runs the 2 functions, and then prints the returned string that was created formatted to specification.
Interesting aspects: While the homework doesn't specify, I decided to make the core function a recursive one in keeping with the recent focus. This gave me some additional experience using them and allowed me to keep the even/odd question as only a matter of if the string is 1 or 2 characters long. I split off the check file function to keep the palindrome function as simple as possible keeping the individual line and overall file elements separate. In order to do that, I have the check file function call the palindrome one and so the core function is then not called by name in the code though it is still run via the function that is.

2: Introduction: Problem 2 has us get a string from a file given in standard in and prints a list of all unique substrings alphabetically. 
Algorithm: The function for this program was required to use recursion and so I included it in the logic. The main function takes a string as an argument and also stores beginning and ending indicators to keep track of the substrings being pulled and a list to store all of the substrings in. To handle edge cases, I use nested if statements which first identify if beginning indicator has passed the length of the string, meaning all substrings have been tried. This immediately goes into the sub if statement which first identifies if the string is empty and if not it goes through preparing the substring list to be returned. To prepare it, the code first converts the list to a set to remove duplicates then convert back to a list. Then it uses nested for loops, taking each substring in one and then running the length of the list to see where it belongs, using the > operator which works on strings with a true response meaning that it should come after alphabetically. Once that is done, the number of strings is appended to the list. Otherwise there are still substrings to get, which is where the recursive function comes in. If the ending counter has reached the end of the string, the function is returned with a new beginning and the character after as a new end. If there is more to go, the function is returned with the current beginning and an iterated end. In order to print the result to standard out, the sys library is called, the file is tested and then run in a for loop to get the text into an alias. This alias is run through the substrings function and then the resulting list is run through a for loop to format the results to specification.
Interesting aspects: Recursion was required but did not exclude loops so I did incorporate a loop in the core function to deal with the alphabetizing. This allowed me to keep that work in an if statement that is only called once the substrings have all been identified avoiding a situation where either it is alphabetizing multiple times for a single string or having to keep it locked off logically to avoid additional effort. Being able to use > saved having to iterate through the characters in the substrings. Using a for loop to get the string seemed a little awkward as there was supposed to only be 1 line but it worked and saved needing to find a write option to put it into an alias.
How to run: Similar to problem 1, ran in git bash and used test files for standard in with screenshots saved in sub folder. Code to run was py /c/location/problem2.py < /c/location/unique_substrings_input_#.txt
3: Introduction: Create a recursive function that reverses a list created as an array, a singly linked list, and a doubly linked list.
Algorithm: The array was done as a list with the required additional base functions. The reversal function for arrays stores an index counter and a string to store the before part of the output. After creating the before string, it looks at edge cases of there being only 1 element in the array or 2. In these cases, the after message is simple to implement and the list is easily updated. Then the function starts on reversing from the top of the list, using specific logic for the first element as it can just be appended to the end of the list and another for flipping the final 2 elements. Otherwise the element is placed in the middle using the index to keep the list up to the prior element and from the next element to the end and then iterates with the index updated.
For the singly linked list, the basic ideas from the previous homework was utilized to build the classes and the required functions, renaming the head and tail the bottom and top. The reversal function uses similar logic as the one for the array, but it stores additional information. This includes a current node, the old top node, the previously moved node, an index, and again a before message string. Reversing the list I did by moving from the bottom rather than the top, I did this as I couldn't find a solution for identifying the node that the top node is linked to without using a loop. I needed the old top as it will always need to have its next node updated to the current node, which will be connected to the previously moved node.
Doubly linked list also followed the base I used for the previous homework, but I didn't keep the sum of the values of the nodes and I didn't need to keep it sorted. This reversal function just needs to keep track of the current node and the before message string. To reverse the order, I started from the top node and flipped the node's previous and next attributes. This is done for each node until I reach the bottom node which needs the same thing done, but also I flip which node is the bottom and which is the top. For all 3, I did use loops for creating the strings to be returned but they did not touch the actual reversing of the lists which I think follows the intent of the instructions.
Interesting aspects: I found it interesting how each implementation involved a different process, with the array moving the top to the bottom, the singly linked list moving the bottom to the top, and the doubly linked list just flipping how the list is read. 4: Introduction: Write a program to read a file from standard in that lists the number of sets of ghostbusters and ghosts matched up, then each match up with coordinates for each on a x y grid. The program should determine if any ghostbusters' proton shots cross streams, returning a message that all ghosts were eliminated if they don't cross and that they weren't eliminated if they do.
Algorithm: The heart of this problem is determining that all proton beams are parallel to each other and that they don't overlap. To do determine this I got the slope of the intersecting line of each set of ghostbuster and ghost to determine parallel-ness and y intercept of those lines to determine if they are overlapping. To get the slope, I divided the difference in y coordinates by the difference in x coordinates for each set, reading individual lines in the file and splitting the elements into a list. For y intercept, if either ghostbuster or ghost had a x coordinate of 0, then I could then take their y coordinate but otherwise I used the slope and the ghostbuster's coordinates to find the intercept. In case of a ghostbuster and ghost sharing a x coordinate, the slope is vertical which I stored using the string 'vert' and then set gave that shared x coordinate in place of the y intercept. Each of these data points were placed into a corresponding list for the file. Once all lines were found, I checked that all of the slopes matched, converting the slope list into a set and confirming a length of 1. If the file passed this test, I also converted the list of y intercepts into a set. If they are all unique, then the length of the set would match the number of sets of match ups which I stored from the file. If a file passed both of these, then all of the ghosts were eliminated and that message was returned.
Interesting aspects: This problem turned out to be fairly easy once I came to the solution of looking at lines rather than needing to create a map and then marking off each proton beam's path as I initially thought. The tip for problem 2 of using a set to determine uniqueness helped with the results part of the program once I put those ideas together. I then needed to make sure that the code followed the logic of slopes needing to be the same and then the y intercepts needing to be unique including the order of the logic.
How to run: The program is stored in the file problem4.py. It was run in git bash against each test file provided as such: py /c/location/problem4.py < /c/location/ghostbusters_input_#.txt.
