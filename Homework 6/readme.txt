Problem 1 - Priority Queue - For this problem, my algorithm brings in the lines from the input as nested lists with each line a sublist. After converting all of the sales times into integers, the algorithm runs the nested list through a function to sort them. This function takes the nested list and creates a copy with list comprehension of it that can be destroyed while keeping the original intact. From there, this copy is put through a while loop that continues as long as there is an element in it. In the loop, I first use list comprehension to pull in the first element from each sub list that has an element and find the minimum of those times. Then a second for loop goes through each sub list, check if the minimum matches the first time in it. If it is a match, the sale is appended to a new list with the register number using the iterable from the inner loop and pops the sale out of the copied list. The inner loop acts as my priority queue having identified the minimum from the 0 index of all sub lists and then the loop itself iterates in order to find where it came from first.

Problem 2 - Heaps - The key function used for this problem was the insert function. After checking the edge case of the heap being empty, the algorithm takes the count of nodes stored in the heap that has already been increased in anticipation of the insertion, and converts it to binary so that a for loop can traverse to where this node should be added. This loop ignores the last character so that it only goes to the open spot's "parent". Whether it should be added as the left child or the right depends on if the left child is already filled in to maintain the complete tree requirement. Then a while loop is used to bubble up lower values. As this was a frequent occurence throughout the logic and would be a consistent swap, I created an internal swap function to handle that.
The extract_minimum function first handles edge cases of if there are no nodes in the heap and if there is just 1. Then it uses the binary of the node count and a for loop to reach the last node added, places its value into the root and deletes the node. After this, a while loop handles any bubble down needed by maintaining as long as a child exists beneath the current node and breaking if no further bubbling down is needed. The original value of the root is held onto until the end at which point it can be returned.
The delete function operates using the binary traversal logic we learned in class to go through each node to check if the value is there until either the last node is checked or the value is found. Once that is finished, if statements check for edge cases beyond one or no nodes existing in the heap which are if the value isn't in the heap or if it is in the last node added. If it is in the last, the node can be quickly removed by getting rid of the link from its parent. Otherwise, my algorithm treats it like the extract min by finding the last node added, putting the value from the last node into the one to be deleted and then deleting that one. Then 2 loops first check if bubbling up needs to occur and then bubbling down.
Build relies on calling the insert function in a for loop going through the values added and was an alternative option for problem 2 but would have required doing the printed outputs in the function itself.
Peek simply looks for the root and returns its value if it exists.
is_empty also looks for the root but returns true if it exists and false if not.
__len__ just uses the stored count from the heap
heap sort uses deep copy from the copy library and then a while loop appending the result of extract_min from the deep copy.
Print_heap and its helper build_ascii I got from Googling "python binary tree class print tree" and then a secondary prompt to Google's AI top down ascii format". 
All of these functions are in minHeap.py and the classes for node and heap in it are called in my driver file which reads the file from standard in, formats the input into a list of integers and then either finishes if the input is blank or goes through a for loop to insert each integer from the file into a heap and then prints the resulting heap.

Problem 3 - Running Medians - For this problem, I added to the minHeap file with additional functions. First a maxinsert that copies the logic of the original insert except at the end it bubbles up when the parent value is less than the child's. Then a extract_max function that copies extract_min except it bubbles down lower values. These are then used in the running_median function that takes a list of values in a for loop, adds them into either a maxheap or a minheap, ensures that the heaps are even, and then calculates the median using the heap's roots. The maxheap utilizes the maxinsert function and the minheap uses the prior insert used in problem 2. The first value is always placed in the maxheap, then if later values are greater than the maxheap's root, they are also placed there so that lower values are not accidently placed in the minheap which should represent the upper half of the sorted values. If they are less than or equal, then they go into the minheap. The heap's evenness is tested using the absolute value of the heap's differences. If they are uneven, the larger one is identified, the root is extracted from it and then is inserted into the other. The extraction for the maxheap uses extract_max and extract_min for the minheap. If the heaps are matched in count then the overall count is even and we need both heap's roots to get their average as the median. If they are not, then the root of the larger one is the median. A previous version had done recursivly rather than with a for loop but it reached a recursion limit on the test median_input11.
The algorithm depends on the middle element(s) are stored in the roots of the heaps. This is why the heaps' counts need to be within one of each other.
