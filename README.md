2. Introduction: This problem asks us to take a file that gives a length of a list of numbers, a target sum to be exceeded, and the list of numbers. The program must return that list of numbers and then give the minimum amount of numbers from the list needed to exceed that target.
Algorithm: The program takes the contents of the file and puts it into a list. Knowing that the first 2 numbers are the number of integers in the list and the target, it stores the second separately and then the third on in its own list. Then the list is sorted in descending order using a built in function and then starts adding up the numbers while keeping count of the numbers used until the target is passed.
Interesting Aspects: The key idea of the program is adding up the numbers from largest to smallest in order to minimize the numbers needed and so sorting was essential to its operation. As there were no restrictions on methodology, I just used the built in function and its descending order option. From there, extracting the information was the other problem to be solved and as we were given an order of how the files are constructed, I used a list and indexing to solve that problem. Through testing, I found that the order of converting the text to integers and sorting mattered as the function differs between integers and numerals in a string for the logic. Therefore converting had to be done prior to sorting.

3. Introduction: This problem was taking a file with a list of points with 2 dimensional coordinates and required a return of the number of right triangles that could be drawn using those points and to do so within a set amount of time.
Algorithm: As discussed in class, the trick to this problem is to look at the slopes of lines between 2 points. In order to avoid an overly long run time, I needed to do this with at most 2 loops. To identify a right angle, I knew that the slopes of perpendicular lines would be opposite inverses and so if I could identify 2 sets of points with lines with such slopes with one shared point then I would have a right triangle. This would only require 2 loops with the outer loop establishing the point at the right angle and the inner loop going through the other 2 points and making matches from there. Within, I had an if statement identifying edge cases where the line would be vertical or horizontal and then calculating slope. A second if statement took those slopes and established the opposite inverse to check against the stored slopes to get a count of right triangles. After looping through all possible combinations, the count of triangles is returned.
Interesting Aspects: I tried to use fractions for slopes to avoid calculation errors which I identified as a potential issue from testing and then had confirmed from the class announcement. I used the greatest common denominator function from the math library to try avoiding this by making all calculated slopes fractions and added additional logic to ensure that the sign of the slope and inverse were correct. Despite this, the code using this method still came up with the alternate answer. Another interesting aspect of my program to point out was the storing of the slopes, using the outer loop as an opportunity to clear slopes from the previous inner loop allowing the code to store them for one right angle point and losing them when the code moves on.
How to run: Similar to problem 2, this was run in git bash from my downloads as: py /c/users/.../triangles.py < /c/users/.../rightangles_#.txt . A screenshot of the results of my tests is in the screenshot folder.
