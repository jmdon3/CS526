Problem 1
My algorithm for a binary search tree started with a node class with a stored value and references to a parent, left child, and right. The tree class itself only has a reference to a root which I used to reference the tree in each function. The add node function first checks if the tree is empty in case the node being added is the root. After that, it goes through a while loop using the value to be added and the current node's to traverse the tree until the empty spot where the node should be placed. If the value is found, an error is raised so as to avoid duplicates. Otherwise, the links are created depending on relative values and the loop is finished.
The delete function similarly goes through a while loop to find the node to be deleted. The algorithm also keeps track of the previous node and the direction moved to assist with repointing efforts. If a leaf is reached without finding the value, a false response is returned. Otherwise, a series of if statements determine if and how many child nodes the node to be deleted has. If the root is being deleted, additional logic is included to repoint the root attribute. If the node to be deleted has no child, just its parent's child reference is updated. If there is one, then it gets pulled up to directly link to the deleted node's parent. If it has 2, I decided to use the method discussed in class of pulling up its left predecessor's largest descendant. This is done with another loop to reach that node, update node to be deleted to its new value and then set the node with its value taken to 0. Then the delete function is called recursivly on 0.
The find node function again uses a while loop to traverse the tree using the given value to reach its logical position. If the value is found, then it returns true and if not then false. If the tree is empty, the algorithm raises a value error.
Print tree stores the current node and its level within the tree, with the node at level 0. Printing the tree horizontally allowed me the greatest control of levels and ensured that nodes wouldn't run into each other in more complex trees. The algorithm itself first ensures that it hasn't done anything by checking that the current node variable hasn't been filled. Then it makes sure that there is a node being referenced in which case it recurses on the current node's right child, then prints the nodes itself and recurses on the left child. Each recurse also tracks the node's level by adding to the variable This causes it to print the largest and right-most positioned node first. The actual printing uses spaces multiplied by the level to properly and efficiently make space.

Problem 2
Following the work in class, my algorithm solves this problem using a state table. The code iterates through the string of dots and dashes with a while loop and calculates an offset to help keep track of how many combinations can be done to reach that character. The offset is calculated on a diagnoal that goes across the previous 3 (or 2 in the case of the 3rd character) characters by number of characters needed for a vowel. For the first 2 characters, I set the offset to 1. With the offset calculated, the algorithm then checks if a vowel can be made from the morse code checking the vowels with 1 character, 2 characters, and 3 separately. The state table is then updated with these results for each group; the offset if a vowel is found and 0 if not.

This program was run in git bash from the downloads folder of my machine:
py /c/users/jmd.../vowels.py < /c/users/jmd.../vowel_input#.txt

Problem 3
For problem 3, my alogrithm takes a similar tack as the one explored for problem 2 by creating lists of offsets and using them to track indexes when viable paths are ignored. To do this, the code uses a series of for loops with the outer one anchoring the start of subsequences and 2 inner loops looking at viable paths for the subsequences. If one is found, it replaces the default 1 with a counter to mark where a path is left off. This method also alternates between sub-lists to keep up with the directions. The same is done only with the lists flipped to account for any subsequence starting from list a.
