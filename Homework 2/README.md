4. Introduction: The final problem had us use nodes again but this time in a sorted doubly linked list. This list would need functions to add a node, delete a node by value, check if a node exists with a given value, print_list the list, give the total sum of the values in the list, sum the middle three nodes in the list, return the median value of the list, and count how many nodes contain a certain value.
Algorithm: The node class for this is identical to the one from problem 2 except that this one also contains a reference to the previous node in the upcoming list to make it doubly linked. The class is similarly created but for this I added on a running sum of the values to help me out with the total function. The add function requires a value and in addition to the alias for the head, I also take one for the tail to save some key strokes. If statements go through the different edge cases: empty list, value is smaller than the existing head, and value is larger than the existing tail. After that the code goes into a while loop testing to see if the current node has a smaller value than the new node. The code only looks at smaller than as if the value is greater than it then it must go there and if it is equal then putting it there saves the code an additional loop(s). After placing the node, the function ends by adding to the count and the sum so that those attributes keep up.
Delete also takes a value for what the node stores that should be deleted. The code first checks that the list isn't empty, returning false if so. Then it goes through the case if it is the head and or the 1 node in the list that is being deleted. Next comes a while loop looking ahead at the next node for a match in keeping with the logic for the singly linked list adding a target alias that catches the next node for link updating purposes. To keep up with the sum and count, each instance of updating references is accompanied by a subtract equals for both. Exists looks for a node with the value. This code jumps right into the loop as there is no difference in logic between identifying a node as existing with a certain value. A potential optimization for this function would be checking the tail and returning a quick false if the value is greater than the node's.
Print_list starts with a check if the list is empty then it moves into a while loop that operates similarly to its counterpart in the singly linked list only the link symbol points in both directions for the double link. Total as mentioned earlier I have kept as a running sum as an attribute for the list making this function a quick return attribute. Sum_middle_three checks for the edge case of fewer than 3 nodes in the list as not possible. Then the function goes through if statements determining where the middle three starts based on the count attribute including whether it is even or odd. Then I add 2 for the end of the middle three for the purposes of ending the loop. Then I go into a while loop iterating until I reach the first middle node, adding its value to a store alias, and then going through the three middle nodes finally returning the sum.
Median goes through the various edge cases of an empty list, 1 node, and 2 nodes before getting into a loop. The loop takes advantage of the rounding division only going up to middle less 1 for index and then either taking the average of the current node's value and the next for even counts or just the next one for odd. For count after determining that the list isn't empty I have it go through a loop, iterating until the node's value is greater than the value to be counted or the list ends. Once it reaches the point where the nodes matches it starts adding to a resolution store alias until the node value goes beyond at which point no more will appear.
