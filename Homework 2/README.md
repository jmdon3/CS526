2. Introduction: This problem asked us to write a code that creates a node class in Python and then a Singly Linked List class that is made up of nodes. The list class needed to include functions that allow you to append a node to the end of the list, prepend a node to the top of the list, insert a node at any point in the list, get the value of a node by using its index, find at what node index a value first appears in the list, len that gets how many nodes are in the list, update that changes the value of a specific node, delete a node by what value it holds, delete_at a node at a certain index, and print_list that gives the full list printed out.
Then we needed to create a separate file that enables the user to take a text file with a script of commands for the list and runs it.
Algorithm: The algorithm for the node class sets it up with the 2 specified attributes, a value and a link to the next node in the to be created list. Then the list class similarly sets up attributes for the head of the list, the tail, and a count of nodes in the list. The append function creates a node and requires a value which is stored in the node. The code first checks if the list has a head and makes the new node the head if it doesn't. If it does, then the current tail of the list needs to now link to the new node and make it the tail. Based on the suggestion in class, the function then increases the count of nodes in the list for me. Prepend is similar to append in that it requires a value and first checks if the list is empty to see if the head and tail both need assigning. The if statement then does the opposite as it is adding to the top of the list, and so needs to connect the new node to the current head and then make it the new head.
Insert uses index and so I start it with the specified check that the index is valid. Despite Python starting its index at 0, I still kept the index equal to the count as valid as it would essentially work as an append. The function then goes through a series of if statements first checking if it is an empty list, then checking if the index is 0, and finally checking if the index matches the count. After these checks, it then starts a for loop that brings it to the node before the given index which it does as the reference for that node will need to be updated to be the new node. Find takes a value to be found as its one argument. It goes through a while loop by using an index counter and an alias that gets reassigned using the next attribute. Within the loop, I used an if statement that breaks the loop if the node value is a match or if it has reached the tail. The function ends using another if statement that checks for a match, returns the index if it does and returns the required -1 if it doesn't.
Len as suggested I just have it return the list count. Update first checks that the index is valid then loops with an index and a node holding alias. Within it is an if statement that updates the value of the node and breaks when the wanted index is hit or else continues the loop. Because a return was not needed for it, I used break to stop the loop as it is what I am familiar with. Delete takes a value and starts by checking if the list is empty as there would then be no node to delete. Then it checks if the head node is a match and goes through updating the head and tail references depending on whether or not there is a second node in the list and updates the node count as one has been removed. Then it goes through a while loop just using node alias, specifically checking that there is a next node to move to. In the loop there are if statements checking the next node's value for a match similar to the update function as the "current" node's next attribute would need to be updated. The function has returns throughout of True if a node has been deleted and False if one can't be deleted.
Delete_at goes by index so it first checks that the index is valid. Because index is used, I use that in addition to the node alias for iterating through the loop to reach the node to be deleted. The next link of the node prior to the one being deleted needs to be updated so the loop only needs to go up to the one prior. As the index has already been checked, I keep the if statements checking if the tail is being removed outside of the loop and update the references in there and then reduce the list count and return the value of the deleted node last.
Print_list first looks if the list is empty in which case a special message is returned. If not, it goes to a while loop just using the node alias for iteration. Inside is an if statement that adds values to an empty string to store the contents of the list that is returned at the end. If the node is the tail then just the value needs to be printed or else the value and then the -> symbol indicating the single link.
The driver file uses a similar base as my solution for homework using the sys library for standard in and standard out and the io library to check that the file type contains readable text. From there I import my custom classes from the problem file and then iterate line by line with a for loop and splits the line up into segments as suggested in class. Within that I have logic to check if the line is blank or has a # signifying a comment. Then the code checks that the first string in the line is a recognizable command for my class and then separately checks if there are too many components to be parsed into a function for the class. Once that has been done, it goes through checking by function type starting with ones with 2 arguments. Then I check for commands with 1 argument that doesn't require some sort of return. For both of these I check that the arguments are positive whole numbers ensuring that the values stay type consistent. If so, I parse out the commands and then attempt to run them using try and exec.
After these I look at functions with a single argument that require a return. For these I again check that the argument is positive and whole but then run 2 different tries with a write to standard out using f statements to give the function, argument, and then the result. The final set of functions are the ones that don't take any argument and have a return. As the others with a return, I split them up into separate tries in standard out. I hard coded these functions as there were only 4 of them total and didn't require many more lines to do so than combined. The driver ends with a final print_list showing the end results.
